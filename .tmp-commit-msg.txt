feat(phase3): edge middleware — per-request nonce CSP + security headers

Defense-in-depth alongside lib/authz.ts. The V2 plan §E explicitly
warns NOT to rely on middleware for authz (compiled Server Actions
and Route Handlers can bypass it — the March-2025
x-middleware-subrequest CVE shape, CVSS 9.1), so this layer is
strictly transport + browser-side:

  Content-Security-Policy   nonce per request, no generic
                            'unsafe-inline' for scripts, font/img/
                            connect allow-lists scoped to the
                            actual upstream surfaces Lar uses
                            (Google Fonts, *.mzstatic.com for
                            iTunes/Apple Podcasts artwork,
                            api.song.link for Odesli)
  Strict-Transport-Security max-age 2 years, includeSubDomains,
                            preload
  X-Frame-Options           DENY
  X-Content-Type-Options    nosniff
  Referrer-Policy           no-referrer
  Permissions-Policy        camera=(), microphone=(self) for the
                            Web Speech API, geolocation=(),
                            payment=(), usb=()
  COOP / CORP               same-origin
  Origin-Agent-Cluster      ?1
  X-DNS-Prefetch-Control    off

How the nonce reaches the inline tags:
  middleware.ts generates a base64(crypto.randomUUID()) per
  request, stashes it on x-nonce of the request, and sets it in
  the CSP on the response. app/layout.tsx awaits headers() and
  stamps nonce={...} on the two inline tags we ship (themeCss
  <style> and the pre-hydration theme-boot <script>). Everything
  else is bundled and served from 'self'; Next's runtime inline
  scripts inherit the nonce automatically.

Matcher excludes /_next/static, /_next/image, and /favicon.ico so
their long-cache pattern isn't broken by per-request headers.

Verified
--------
- Build clean (Middleware route compiled at 34.9 kB). HEAD on /
  returns the full headers set with a fresh nonce in CSP every
  request (live-verified the CSP string includes
  `'nonce-<base64>'` on both script-src and style-src).
- Page renders cleanly under the policy — 1 nonce-stamped <style>
  (themeCss) + 13 nonce-stamped <script> tags (Next runtime
  inherits the nonce), zero CSP-violation reports in the live
  browser console (all console errors observed are unrelated
  Chrome extension noise, present before this change too).
- LAR_KILL_SWITCH=1 surfaces as an X-Lar-Kill-Switch:1 response
  header for ops dashboards (matches lib/authz.ts contract).
- 16/16 typecheck, 16/16 test workspaces green (23 portal specs
  unchanged), prettier --check clean.
